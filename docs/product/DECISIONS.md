## D1 · 应用形态：先网页，后桌面壳

**状态：已确认（方向级 · 甲）**  
**决策：** 第一阶段 **甲：纯 Web 应用 + 本地项目文件夹 + 独立 MCP Bridge**；桌面壳放后期。

| 选项 | 含义 |
|------|------|
| **甲（已选）** | 纯 Web + 本地文件 + Bridge；壳在后期 |
| 乙 | 第一版即 Tauri |
| 丙 | 仅网页 + 分享链接 |

**原因：** AI 实时操作画布的关键是本地 Bridge + MCP，不依赖桌面壳；Tauri 只做安装体验薄壳。

## D2 · 产品定位：AI 可读写的设计中间层

**状态：已确认（方向级）**  
**决策：** 不做「另一个 Figma」，不做 v0 式全栈代码生成器。

**一句话：**  
用组件拼界面，用 MCP 让 AI 帮你画，用一套设计生成多套系统的实现。

**差异化：** AI 可操作画布 · 语义组件与页面流 · 多设计系统导出 + 资源库  

**明确不做（短期）：** 钢笔/布尔/像素修图 · 多人实时协作 · 正面比拼通用设计能力

## D5 · 账号与同步：本地优先 + 可选登录 + 用户自控同步

**状态：已确认（方向级 · 2026 对齐）**  
**决策：**

1. **默认完全本地**：项目与个人样式存本机，无强制账号。  
2. **登录可选、永不强制**：登录只用于「同步 / 备份 / 跨设备」，不锁功能。  
3. **同步入口开放、由用户自选**：用户自己填自己的同步端，例如：  
   - GitHub 仓库  
   - WebDAV（坚果云、Nextcloud 等）  
   - S3 / 兼容对象存储  
   - 自定义 HTTP 端点  
4. **个人样式可保留**：每人自己的主题、色板、默认组件偏好、图标收藏，与「官方 Pack」分层存放，互不覆盖。  

**原因：**  
贴合开源/无服务器立场；尊重隐私与可控性；避免做成「必须注册才能用」的 SaaS。

**产品原则一句话：**  
> 打开就能用；登录只是选项；数据去哪，用户说了算。

---

## D6 · 个人样式分层

**状态：已确认（方向级）**  
**决策：** 样式分三层，避免「改了一处全局全变」：

| 层 | 内容 | 默认归属 |
|----|------|----------|
| 系统层 | Material / shadcn 等官方 Pack 规则 | 产品自带 |
| 个人层 | 用户主题、色板、组件默认值、收藏 | 仅本机（可再同步） |
| 项目层 | 某个设计的 palette / theme 覆盖 | 随项目文件 |

个人层可「存为我的样式」「应用到当前项目」；不自动改系统层。
