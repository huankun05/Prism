# 开发方案（当前版）

> 更新：并入 D5（可选登录 + 用户自控同步）、D6（个人样式分层）。  
> 原则：**本地优先 · 登录可选 · 同步自选 · 个人样式可保留**。  
> 配套：`DECISIONS.md`（决策摘要）· `开源UI与组件策略.md`（组件质量）· 调研文档。

---

## 0. 产品一句话（执行时对照）

**给 AI 开发者用的本地优先 UI 设计画布：**  
用组件拼界面；AI 通过 MCP 直接帮画；每人保留自己的样式；项目存在本地；需要时再用自己的方式同步；导出提示词/结构，对接多套开发体系。

不做：通用设计软件全家桶、强制云账号、短期多人白板。

---

## 1. 能力分层（架构目标）

```
┌─────────────────────────────────────────┐
│  UI：画布 / 项目库 / 资源库 / 设置        │
├─────────────────────────────────────────┤
│  个人层：我的主题、色板、收藏（可同步）    │
├─────────────────────────────────────────┤
│  项目层：design.json（本地文件，可同步）  │
├─────────────────────────────────────────┤
│  系统层：Pack（M3、shadcn…）只读规则      │
├─────────────────────────────────────────┤
│  通道：MCP Bridge · 同步端（用户自配）    │
└─────────────────────────────────────────┘
```

- **无后端账号也能用满** 主路径（画、存、AI 桥、导出）。  
- 登录/同步是「插在通道上的可选插件」，不是地基。

---

## 2. 阶段总表

| 阶段 | 名称 | 核心问题 | 完成时用户能感到什么 |
|------|------|----------|---------------------|
| **0** | 底座 | 能跑、有名字、可扩展 | 打开的是我们的产品 |
| **1** | 本地项目库 | 东西存在哪 | 项目像对话列表，文件在本地 |
| **2** | MCP 桥 + 实时改 | AI 怎么帮画 | 一句话，画布长出界面 |
| **3** | 个人样式层 | 每个人自己的样子 | 主题/色板/收藏是我的，不丢 |
| **4** | 资源库 | 组件图标从哪来 | 秒搜秒拖，导入即用 |
| **5** | 设计系统 Pack | 一套设计多套皮 | 一键 Material ↔ shadcn… |
| **6** | 自控同步（+可选登录） | 换电脑/备份 | 用户自己的 GitHub/WebDAV/… |
| **7** | 模板 + 更多 Pack | 冷启动更快 | 精品模板；Ant 等国内系统 |
| **8** | 桌面壳（可选） | 像软件一样安装 | 安装包 + 内嵌桥与同步 |

> 与旧版差异：原「资源库在 Pack 前」微调为 **个人样式在资源库前**——你明确要求「先能保留每个人自己的样式」；同步放 Pack 之后，避免过早做账号复杂度。

---

## 3. 各阶段说明

### 阶段 0 · 底座（1 个迭代）

**做什么**

- 跑通 m3e-canvas（依赖、构建）  
- 产品命名与基础品牌（Logo、标题、README 致谢 MIT）  
- 目录与代码预留：`personal` / `sync` / `bridge` 扩展位（可先空壳）  

**不做：** 新功能、重重构  

**验收：** 浏览器打开自有品牌画布，能拖组件、能导出提示词  

---

### 阶段 1 · 本地项目库

**做什么**

- 项目列表 UI（新建 / 打开 / 重命名 / 删除 / 封面或摘要）  
- **项目 = 本地文件夹**（`design.json` + `meta.json` + 可选 `assets/`）  
- 浏览器侧：File System Access 优先，不支持则「下载/打开文件」兜底  
- 打开时迁移原 localStorage 草稿  

**验收：** 关掉浏览器再开，项目还在；文件夹可在资源管理器里看到  

---

### 阶段 2 · MCP 桥 + 实时改画布

**做什么**

- 画布连接本地 Bridge（WebSocket 或本地 HTTP）  
- 极小 MCP Server，工具建议最小集：  
  - `list_projects`  
  - `read_design`  
  - `write_design`（整页或 patch）  
  - `add_part` / `update_part`（可第二步再加）  
  - `get_canvas_state`（当前打开哪个项目）  
- 画布监听变更并刷新；AI 改动可撤销、可高亮来源  

**验收：** 在 MiMo/Claude Code 里配好 MCP，说「画一个设置页」，画布实时出现  

**为何重要：** 产品与普通画布工具的分水岭  

---

### 阶段 3 · 个人样式层（本次并入重点）

**做什么**

- 样式分层落地（系统 / 个人 / 项目）  
- 「我的样式」：主题、默认色板、字体偏好、形状尺度、组件收藏  
- 操作：**存为我的样式**、**应用到项目**、**重置为系统默认**  
- 导出：`my-style.json`（可手动备份）  

**明确不做（本阶段）：** 账号、云端同步（个人样式仍只在本地，文件可手动带走）  

**验收：** 我调了一套紫黑主题 → 存为「我的样式」→ 新项目一键套用；系统 Pack 不被污染  

---

### 阶段 4 · 资源库

**做什么**

- 图标：Lucide / Heroicons / Tabler + 已有 Material Symbols；搜索、预览、复制名、拖入画布  
- 组件画廊：Kind × 主题预览  
- 品牌：拖入画布时遵守项目/个人层主题  

**质量标准（见组件策略）：** 秒搜秒拖；默认颜值；来源与许可标注  

---

### 阶段 5 · 设计系统 Pack

**做什么**

- 抽出 Pack 接口；现有 M3 → `packs/m3`  
- 第二套：`packs/shadcn`（或 tailwind 风格）  
- 全局切换器：画布即时换皮；提示词按 Pack 分流  

**验收：** 同一设计切换后仍像「那套系统」，布局不崩  

---

### 阶段 6 · 自控同步 + 可选登录（本次并入重点）

**做什么**

**同步（用户自配端，按序交付）**

| 优先级 | 端 | 说明 |
|--------|----|------|
| 第一版 | **二选一：GitHub 仓库 或 WebDAV** | 配置简单、文档好写；建议先 WebDAV（个人网盘场景更直观）或先 GitHub（开发者向） |
| 后续 | S3 / 自定义 HTTP | 开放协议文档，社区可接 |

同步对象建议：

1. 项目文件夹  
2. 我的样式 `my-style.json`  
3. 可选：全局设置  

**登录（可选，可与同步拆开）**

- 无账号：功能完整（画、存、桥、导出）  
- 有账号：仅用于托管同步（若将来有官方托管）或第三方 OAuth（如 GitHub 登录后一键推仓库）  
- **禁止：** 登录墙、把「未登录」做成残缺版  

**验收：** 不登录能用；登录后（或只配 WebDAV）能把「我的项目 + 我的样式」同步到另一台电脑  

---

### 阶段 7 · 模板 + 更多 Pack

- 精品模板 8–12 个（登录、设置、列表、详情…）导入即改  
- Ant Design / Element Plus 等 Pack  
- 模板可含「套用某个人样式」选项  

---

### 阶段 8 · 桌面壳 Tauri（可选）

- 安装体验、菜单、自动启动 Bridge  
- 同步配置做成设置页而非手写 JSON  
- 前端与阶段 0–7 的 Web 版共用

## 5. 非目标（本方案内明确不做）

- 实时多人协作光标  
- 企业权限 / 组织管理后台  
- 应用商店式插件市场（社区 PR 先于市场）  
- 与 Figma 文件双向同步（可作远期研究）  
- 强制统一云存储  

---

## 6. 开源与许可（执行约束）

- 基座保留 MIT 与原作者致谢  
- 图标与 Pack 优先 MIT / Apache-2.0  
- 避免 NC 素材与来源不明付费 UI Kit  
- 项目本体建议 MIT 或 Apache-2.0  

---

## 7. 你拍板后即可动工的点

1. ~~形态~~ → 已定甲  
2. ~~同步与登录~~ → 本地优先 + 可选登录 + 自控同步  
3. **产品名**（阶段 0 动工前建议有）  
4. **同步第一端**：GitHub 还是 WebDAV（阶段 6 才实现，可先选倾向）

## 8. 讨论用：本方案如何回应你的三点

| 你的要求 | 方案落点 |
|----------|----------|
| 每个人保留自己的样式 | 阶段 3 个人层 + D6 分层；可导出 my-style.json |
| 后续可选登录 | 阶段 6；永不强制；不锁核心功能 |
| 自定义同步入口，用户自己同步 | 阶段 6：WebDAV / GitHub / S3 / 自定义端；配置归用户 |
