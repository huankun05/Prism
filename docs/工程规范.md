# 工程规范（Prism）

> 所有功能变更必须走完本流程，禁止「顺手改一堆、文档不更新」。

## 1. 工作流（强制顺序）

```
方案确认 → 实现 → 自检 → 测试 → 文档 → 提交
```

| 步骤 | 要求 | 不通过则 |
|------|------|----------|
| **1. 方案** | 先说明改什么、为什么、影响面、验收标准；大改先写入 `docs/` 或 PR 描述 | 不写代码 |
| **2. 实现** | 按方案改；不夹带无关重构 | 拆 PR / 拆提交 |
| **3. 自检** | 可读性、边界、是否破坏既有行为；清理临时文件 | 回改 |
| **4. 测试** | `npm run typecheck` + `npm test` 必须全绿 | 禁止提交 |
| **5. 文档** | 更新 README（若用户可见）、`docs/PROGRESS.md`、相关设计文档 | 禁止提交 |
| **6. 提交** | 见提交信息规范；推送至约定仓库 | — |

## 2. 质量红线

- **可用**：主路径可运行；`npm run build` 能通过（阶段允许后补的除外，须在 PROGRESS 标明）
- **鲁棒**：外部输入（打开文件、AI 生成 JSON、用户编辑）要有校验，失败可恢复
- **性能**：不引入明显卡顿；大列表/大画布避免每次全量无必要重算
- **不散乱**：临时试验文件不入库；测试输出不进主目录；死代码删掉不留「以防万一」

## 3. 文件与目录

| 类型 | 约定 |
|------|------|
| 产品/决策文档 | `docs/`（开发方案、决策、调研、进度） |
| 组件 UI | `components/` |
| 纯逻辑 | `lib/` |
| 路由页面 | `app/` |
| 公共静态资源 | `public/` |
| 临时调试 | 本地修改，**不要 commit**；确需保留的测试进 `*.test.ts` |

定期清理（建议每个里程碑做一次）：

- 删除未引用的临时脚本、截图、下载物  
- 归档过时设计稿到 `docs/archive/`  
- 检查 `.gitignore` 是否覆盖 `out/`、`node_modules/`、`.next/`、本地 env  

## 4. 测试与检查命令

```bash
npm install          # 安装
npm run dev          # 本地预览
npm run typecheck    # 类型
npm test             # 单元测试（vitest）
npm run build        # 静态构建（发布前必跑）
```

新增逻辑优先补测试；改 `lib/` 纯函数几乎必须有对应 test。

## 5. 提交信息

格式：

```
<type>: <简短说明>
```

| type | 何时用 |
|------|--------|
| feat | 新功能 |
| fix | 修复 |
| docs | 仅文档 |
| chore | 构建、依赖、清理 |
| refactor | 行为不变的重构 |
| test | 测试 |

示例：`feat: rename product to Prism and default UI to Chinese`

## 6. 仓库

- 远程：`https://github.com/huankun05/Prism.git`
- 主分支：`main`
- 推送前：测试绿 + 进度文档已更新
- 禁止提交密钥、个人 token、超大二进制临时文件

## 7. 语言与文案

- 界面默认 **中文**；保留英文切换；日/韩文案暂留代码
- 用户可见新字符串须进入 i18n，禁止只写中文硬编码在 UI
- 代码注释可用英文或中文，但同一文件保持一致

## 8. 开源合规

- 基座 m3e-canvas：**MIT © lnkiai**，保留 `LICENSE` / `NOTICE` 及致谢
- 第三方资源优先 MIT / Apache-2.0
- 新增依赖记录在 `package.json`，注明用途于 PR/提交说明（复杂依赖）

## 9. 里程碑与清理

每个阶段结束（见 `docs/开发方案.md`）：

1. 全量 typecheck + test + build  
2. 更新 `docs/PROGRESS.md` 与 README  
3. 清理临时文件，归档过时文档  
4. 打 tag（可选）：`v0.x-m0` 等
