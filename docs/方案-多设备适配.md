# 多设备适配方案（手机 / 平板 / 桌面·网页）

> 状态：**方案已定，文档同步**  
> 关联：`public/design-system.md` · 阶段 2 AI 工作台 · 基座已有 phone/desktop Frame  
> 日期：2026-09-15

---

## 1. 业界怎么做（调研结论）

| 产品/体系 | 做法 | 对我们的启发 |
|-----------|------|----------------|
| **Figma** | 多 Frame 并排；Auto Layout + 约束；无「自动一套代码多端」 | 我们也是 **多 Frame 并排**，不是一套 DOM 自动变形 |
| **Figma Sites / Web** | 断点是不同设计稿或响应式规则 | 原型阶段先 **显式画断点** |
| **Material 3 布局类** | Compact（手机）/ Medium（折叠屏/平板竖）/ Expanded（桌面/平板横）；**同一设计系统、不同结构规则**（底导 ↔ 导航栏） | **风格共享、结构分层** 正是我们要的 |
| **Stitch / AI Studio 类** | 先定系统与模板，再生成具体屏 | 生成时声明 **设备目标** |
| **Excalidraw / 白板** | 无设备语义 | 不学 |

**一句话：**  
**风格是一套（token/预设），布局是按设备家族拆的（导航位置、密度、内容栏）。**  
不是「改一个宽度所有东西自动完美」，而是「同族设备可复用，跨族结构要换」。

## 2. 我们的产品模型（决策）

### 2.1 三层

```
① 设计系统层（全局一套）
   色板 · 圆角 · 字体 · 动效 · 组件观感
   → 风格预设、theme、paletteKey

② 设备家族层
   compact（手机）
   medium（平板竖屏 / 折叠展开一部分）
   expanded（桌面 / 网页 / 平板横屏）

③ 页面实例层
   每个「产品页面」在画布上 = 1..N 个 Frame
   同名 Frame = 同一页面的不同设备宽度（提示词里写成一屏多宽）
```

### 2.2 你问的两种情况

#### A. 桌面和手机不一样（导航位置不同），风格一样

**会设计两个（或多个）Frame，共用一套风格，不硬塞进一个 Frame。**

| | 手机 Compact | 桌面 Expanded |
|--|--------------|---------------|
| 导航 | **底部导航栏** bottomNav | **侧边导航栏** navRail |
| 顶栏 | 全宽 topAppBar | 可简化或与 rail 并存 |
| 内容 | 单栏 16dp 边距 | 单栏或更宽；边距仍按系统 |
| 密度 | 中等 | 可更疏或双栏（后期） |

基座已有能力：把 Frame 从手机切到桌面时，**carryFrame** 会重排，导航会按规则变成 rail 方向（见 `setFramePreset` / `carryFrame`）。  
AI 生成「双端」时：**同名两屏**（如 `home`@手机 + `home`@桌面），提示词已要求同名 = 一屏两宽。

**不是**「先只画手机再指望它自己长出桌面」——除非你手动切 preset 做迁移；AI 路径是 **主动铺两套结构**。

#### B. 手机 vs 平板（都是安卓，屏幕占比不同）

**分两档，不要一上来做 20 种机型：**

| 档 | 尺寸建议 | 策略 |
|----|----------|------|
| **手机（已支持）** | 412×892 | 默认 Compact |
| **平板竖（建议新增）** | **834×1112**（类 iPad Pro 11 竖，也接近不少安卓平板竖屏逻辑） | **Medium：结构常可沿用手机**——仍是底导或可选 rail；边距可 24；一屏信息更多 |
| **桌面（已支持）** | 1280×800 | Expanded：rail + 宽内容 |

**手机 → 平板竖：** 同一页面可以 **同一布局语言直接换更大 Frame**（自动 carry 宽度），再手动加一行内容或改边距。多数 App 这样够用。

**手机 → 桌面：** **必须换导航结构**（底导 ↔ 侧栏），不能只拉宽。

**切换查看：**  
同一设计文件里多 Frame 并排 = Figma 式「对照」。  
后期可加「设备预览」：预览模式按当前 Frame 尺寸全屏看，而不是永远按手机预览。

## 3. 画布与 AI 的分工

| 用户动作 | 系统行为 |
|----------|----------|
| 选风格预设 | 只改 ①，所有设备 Frame 一起变观感 |
| 手动加桌面 Frame / 切 preset | ③ 尺寸变 + carry 布局规则 |
| AI「设备目标=手机」 | 只生成 Compact 屏 |
| AI「设备目标=桌面」 | 只生成 Expanded；导航用 rail 语义 |
| AI「设备目标=双端」 | 同一产品页 **手机 + 桌面 各一 Frame，同名**；导航分别用底导 / rail；**风格字段共用** |
| 预览 | 按选中 Frame 的宽高预览（已有 tap-through） |

**风格永远一套；结构按设备家族生成。**

## 5. 设计系统补充规则（已写入 design-system）

### Compact（手机）

- 底导 + 顶栏；单栏；边距 16  

### Medium（平板竖）

- 可沿用底导或改侧栏；边距 20–24；卡片可更宽  
- 一屏可容纳更多列表行  

### Expanded（桌面/网页）

- **主导航用 navRail（侧栏）**，不要底导顶满桌面  
- 内容区不要铺满 1280 仍用手机 16 边距感——内容列可 max 约 720–960 居中或左对齐 rail  
- 主 CTA 仍唯一；信息密度可高于手机  

### 配对规则（AI / 人工）

1. 同一产品页 → **相同 `frame.name` / id 语义**（如 `home`）  
2. 风格字段只在 Doc 顶层写一次  
3. 导航结构允许不同  
4. 文案一致

## 6. 回答你的原话

| 问题 | 答案 |
|------|------|
| 桌面和手机导航不一样，会同时设计两个吗？ | **是。** 两个 Frame，同一套风格；结构（导航）不同。AI 双端模式会主动做这件事。 |
| 还是按方案改？ | 也可先只做一端，再用 Frame preset **迁移**到另一端再改结构；完整产品建议两端并存对照。 |
| 手机和平板只是占比不同，能直接切换查看吗？ | **同族（手机↔平板竖）**：同一布局可换更大 Frame，画布并排对照；**跨族（手机↔桌面）**：要换导航。后期加「按设备预览」。 |
| 只做手机行不行？ | 可以作为 V1；要桌面/网页就必须 Expanded Frame。 |
