# Prism 全站 UI 设计改造方案

> 日期：2026-09-16  
> 性质：对照专业工具的诊断与执行计划（非空话）  
> 执行原则：改版后必须截图对比，不能只改代码不看结果。

---

## 0. 诊断（基于真实截图 + 代码）

### 项目库（第一眼）

| 问题 | 现状 | 专业工具 |
|------|------|----------|
| 信息架构 | 头卡 + 工作区行 + 警告条 + 空状态四段「层叠」 | Figma：顶栏一行 + 列表/网格，少噪音 |
| 头部 | 大圆角白卡浮在背景上，标题「项目库」另起一行像补丁 | 顶栏原色铺满，Logo/标题/操作同一行 |
| 空状态 | 大虚线框占半屏，没有行动感 | 小空态 + 主按钮直接开干 |
| 警告文案 | 浏览器不支持等说明常驻，劝退 | 仅在失败时 toast；正常不占位 |
| 按钮 | 圆角胶囊像 demo | 紧凑、图标+文字、hover 有层次 |
| 密度 | 偏松、偏「卡片实验室」 | 工具向：更紧、更整齐 |

### 编辑器

| 问题 | 现状 |
|------|------|
| 浮动元素过多 | 顶中工具、底左 AI、底右缩放、左上项目库、右上提示词……像仪表盘 |
| 外壳与文档色 | 已拆 `ui`/`p`，但按钮仍偏「圆角圆钮 M3」而非专业画布 |
| 侧栏 | 已修滚动，但内容密度与标题栏仍是「App 草稿」级 |
| 组件基线 | `IconBtn` 圆形 36px、`Segmented` 40px 偏大，工具应 28–32px |

### 组件库现状

`components/ui.tsx` 的 IconBtn / Segmented / Tile：Material 画布组件套在编辑器上，**角色混淆**。画布要 Material；**外壳要 Figma/Linear 向**。

---

## 1. 设计原则（执行）

1. **工具感**：外壳灰阶 + 品牌色点缀；少大圆角胶囊  
2. **一级视觉 = 画布**；UI 不抢戏  
3. **密度**：图标按钮 32px；面板内边距 12/16；标题栏 48px  
4. **一层结构**：禁止「卡里套卡」  
5. **空状态有出口**：一个主 CTA，不要说明书  
6. **截图验收**：改完必须对比截图

## 3. 分屏改造清单

### A. 项目库（本迭代必做）

- [ ] 全宽顶栏：Logo | 名称 | 工作区状态 | 右操作  
- [ ] 去掉大头卡与常驻警告条  
- [ ] 空态：居中紧凑 + 「新建项目」主按钮  
- [ ] 项目卡片：统一边框、hover 提升、操作次级化  
- [ ] 创建表单：内联一行，不是大表单卡  

### B. 编辑器顶栏（下一步）

- [ ] 项目库 / 保存 / Bridge 收成 **一条** 44px 顶栏，与左栏同高  
- [ ] 中部工具单独成组，减少第三第四堆  

### C. 编辑器底栏（下一步）

- [ ] 「让 AI 画」固定左下；缩放固定右下；中间留空  

### D. 组件（下一步）

- [ ] 新增 `lib/ui-chrome.tsx`：`ChipBtn` `ToolIcon` `PanelHeader`  
- [ ] 编辑器外壳逐步换用；画布仍用 M3  

---

## 4. 验收

1. 项目库截图：看起来像设计工具首页，不是模板站  
2. 换项目主题时外壳仍中性  
3. 无挤压、无叠层  
4. typecheck/test 绿  

---

## 5. 本迭代交付范围

**只做 A.项目库重设计 + 外壳 token 落地**，截图对比后继续 B/C/D。  
不在本迭代做：画布组件视觉、多语言文案全量、动效打磨。
