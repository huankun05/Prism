## 2. 关键发现

### 2.1 浏览器：用户可见文件夹 API 不是全平台都有

Can I use（2026-08 数据）`showDirectoryPicker`：

| 浏览器 | 支持 |
|--------|------|
| Chrome / Edge | ✅ |
| Safari / Firefox | ❌ |
| 全球份额 | 约 **76%** |

含义：

- **文件夹项目库只能是 Chromium 主路径**
- 必须有 **降级路径**，否则约 1/4 用户「不能用」或白屏——这不符合可用性/鲁棒性要求

### 2.2 OPFS 不能替代「用户自己的文件夹」

MDN：OPFS 源私有、**用户在资源管理器里看不到**，清站点数据会丢。  
适合当「高速内部缓存」，**不适合**「项目存在用户盘上、可备份可迁移」。

我们的产品承诺（D5：数据去哪用户说了算）→ **主存储必须是用户可见目录**；OPFS/IndexedDB 只可作句柄缓存或缓存加速。

### 2.3 Excalidraw 模式：浏览器自动存 + 开放格式文件

- 托管版：**local-first 自动保存到浏览器**
- 人可导出 **`.excalidraw` 开放 JSON**
- 另有协作、分享链接、端到端加密

**借鉴：** 自动保存、开放格式、导出必稳。  
**不照搬：** 它没有「像文件夹里的项目列表」那种 Vault 感；我们阶段 1 要的是更像 Obsidian/文件管理的可见项目库。

### 2.4 tldraw 模式：key → IndexedDB；高级用 snapshot

- `persistenceKey`：多文档自动存 IndexedDB  
- `getSnapshot` / `loadSnapshot`：自定义后端  

**借鉴：** 文档与会话状态分离；自定义存储层清晰。  
**不照搬：** 纯 IndexedDB 仍「文件不在用户盘上」。

### 2.5 Obsidian 模式：库 = 用户选择的文件夹

用户先建/选一个 **Vault 文件夹**，笔记以文件形式存在里面。  
这是「本地项目库」最强的用户教育样本：**目录即产品数据面**。

**借鉴到 Prism：**

```
用户选定的 Prism 工作区/
  项目A/design.json
  项目B/design.json
```

### 2.6 设计工具对照（简）

| 工具 | 项目在哪 |
|------|----------|
| Figma | 云端（非本地库） |
| Penpot | 偏团队/服务器 |
| 传统 Sketch | 单文件 .sketch |
| Excalidraw | 浏览器 + 可导出文件 |

我们要的中间态：**浏览器应用 + 用户本地工作区文件夹**（介于 Sketch 单文件与 Obsidian 库之间）。

## 4. 技术选型对照（推荐怎么落）

| 层 | 推荐 | 不用谁 / 为何 |
|----|------|----------------|
| 主存储 | `showDirectoryPicker` 用户目录 | OPFS 用户不可见 |
| 句柄持久 | IndexedDB 存 DirectoryHandle | localStorage 存不了复杂对象 |
| 文档格式 | 现有 Doc JSON；旁路 `meta.json` | 不改画布 schema |
| 自动保存 | 内存变更 → ~500ms 防抖写入 | tldraw/Excalidraw 常见节流 |
| 无 FSA | 现有导出/导入 + localStorage 草稿 + 最近 | 不假装有文件夹 |
| 校验 | 复用 `isProject` | 已有 |

---

## 5. 推荐结论（给阶段 1 方案用）

1. **产品形态：** 采用 **「Prism 工作区文件夹」**（Obsidian 式），子文件夹 = 项目。  
2. **不是** 每次单独选一个项目文件夹（多项目会话太吵）；工作区一次授权，长期用。  
3. **自动保存：** 默认开（Excalidraw/tldraw 惯例）；顶栏显示状态。  
4. **旧草稿：** 首次启动 **提示导入为项目**，不静默覆盖。  
5. **浏览器策略：** Chromium 全功能；其它浏览器 **必须降级可用**（导入导出+草稿），不阻塞阶段 1。  
6. **OPFS：** 本阶段不用作主存储。  
7. **清单裁剪：** 阶段 1 只做「必须 + 应该」表；封面/搜索/同步全部后置。
