# Prism 设计系统 v0.1（给画布与 AI 生成用）

> 目标：生成的界面看起来像「成套产品」，而不是组件堆砌。  
> 对标思路：Material 3 角色色板 + 刻意留白/节奏 + 信息层级；Stitch / AI Studio / Figma 的共同点是 **先定系统，再画屏**。

---

## 0. 三条铁律（先于任何像素）

1. **一屏一主任务**：每屏只有一个主要目标（列表 / 详情 / 设置…），次要动作降级。
2. **节奏先于装饰**：垂直间距用 8 的倍数；同组密、组间疏。
3. **层级靠对比，不靠乱加框**：标题更重、正文更轻、辅助更淡；能用色阶就少描边。

---

## 1. 间距与网格

| Token | 值 | 用途 |
|-------|-----|------|
| space-1 | 4 | 图标与文字、紧凑元素内 |
| space-2 | 8 | 控件内边距、列表项内垂直 |
| space-3 | 12 | 卡片内边距（紧凑） |
| space-4 | 16 | **屏幕左右边距**、组间距标准 |
| space-5 | 20 | 卡片内边距（舒适） |
| space-6 | 24 | 区块之间 |
| space-8 | 32 | 大区块 / 英雄区下方 |
| space-10 | 40 | 空状态、页脚呼吸 |

规则：

- 所有坐标尽量对齐 **16dp 左右边距**（CONTENT 宽）。
- 同一垂直列表：项间距 **0**（连接组）或 **8**（松列表）；组与下一组 **≥16**。
- 顶栏底边到首个内容 **≥12**，通常 **16–24**。
- 底部导航上方内容结束点 **≥ 导航高度 + 16**，不要贴着导航。

## 2. 色彩（只用角色，不许随手乱色）

画布已有完整 Palette。生成时优先：

| 角色 | 用于 | 避免 |
|------|------|------|
| primary / onPrimary | 主按钮、选中态 | 大面积铺满背景 |
| primaryContainer | 图标容器、选中芯片 | 正文文字 |
| secondaryContainer | 次要图标底、tonal 按钮 | 与 primary 抢主操作 |
| surface / surfaceContainer… | 页面与卡片分层 | 当作文字色 |
| onSurface | 主文字 | 背景 |
| onSurfaceVariant | 副文字、图标 | 主标题 |
| outline / outlineVariant | 分割线、弱描边 | 当主按钮描边（按钮用 outline 时用 outline） |
| error | 破坏性操作 | 装饰 |

预设色板顺序建议（更有产品感时）：**blue → teal → purple → coral**。  
`theme.emphasized = true` 时标题会更「Expressive」，适合消费类 App；工具类可保持 false。

---

## 3. 字体层级（语义角色）

即使画布暂时用同一字体家族，也要用 **粗细/尺寸对比** 表达角色：

| 角色 | 建议 | 示例 |
|------|------|------|
| 标题屏 | 大、中粗 | 顶栏标题、详情大标题 |
| 区标题 | 中、中粗 | 「基本信息」「相关任务」 |
| 主列表项 | 正文中粗 | 任务名、设置项名 |
| 辅助 | 小、轻色 | 时间、状态、说明 |
| 操作 | 中粗、primary | 按钮标签 |

规则：**一屏最多 2–3 个「很重」的字**。不要所有文字都加粗。

---

## 4. 组件密度（高级感主要来自这里）

### 列表项

- 高度信息完整：icon + 主标题 + 副文本（时间/状态）。
- 副文本用 onSurfaceVariant，不超过一行为主。
- **连接列表**（axis: y）用于同质项；末项不要悬空巨大空白。
- 可选结尾 icon 表示状态（check、chevron 语义图标）。

### 按钮

- **每屏主操作 ≤1 个 filled**；其余 outlined / text。
- 主按钮靠近内容底部或拇指区，不与导航打架。
- 按钮组：主次并排时，主左次右，间距 8–12。

### 顶栏

- filled + 系统 primary 适合强品牌；列表页也可用 tonal 减淡。
- 左返回/菜单，右最多 1–2 个动作图标。

### 卡片

- 用于「一块独立信息」，不要整页都是 card。
- 卡片内：图区（可选）→ 标题 → 正文；内边距 16–20。
- elevation：elevated 适合详情英雄卡；列表内更常用 tonal/filled 平铺。

### 底部导航

- 固定屏幕底部；3–5 项；选中项有 indicator 感（selected 索引正确）。
- 内容区不要盖住导航。

## 5. 屏幕模板（先套模板再改内容）

### A. 列表屏

```
TopAppBar
16
List × 3–6（连接或 8 间距）
24
操作行（主+次按钮 或 FAB 语义）
…
BottomNav（可选）
```

### B. 详情屏

```
TopAppBar（返回）
16
Hero 卡片或大标题块
16
属性列表（2–4 行）
24
主操作按钮
```

### C. 表单/设置屏

```
TopAppBar
16
分组标题 + 开关/列表项
16
分组标题 + …
```

### D. 空状态

```
TopAppBar
居中：图标容器 + 短句 + 一个主按钮
```

---

## 6. 流程与导航

- 多屏用 **语义命名**：`home` / `detail` / `settings`，不要 `Screen1`。
- 列表 → 详情：`action.to = detail`，transition `slide`。
- 详情返回：顶栏 icon `arrow_back`，`action.to = home`，`slideLeft`。
- 底部导航 selected 与当前屏一致。

---

## 7. 反例（不要这样生成）

- 一屏 5 个 filled 按钮  
- 坐标乱跳、边距 3/7/19 不齐  
- 所有列表项只有 label，没有副文本节奏  
- 底部导航浮在内容中间  
- 卡片套卡片  
- 用 error 色当品牌色  
- 两屏之间 0 间距叠在一起  

---

## 8. 给 AI 的生成检查清单（提交前自检）

- [ ] 左右边距统一 16  
- [ ] 垂直节奏符合 space token  
- [ ] 主操作唯一、位置合理  
- [ ] 文字有主/次/辅至少两级  
- [ ] 列表密度均匀  
- [ ] 导航与内容不冲突  
- [ ] 屏名与跳转语义正确  
- [ ] 主题 paletteKey 与 dark/shape 成套  
- [ ] 看起来像「一个产品的两个页面」，不像两次随意涂鸦  

---

## 9. 与画布能力的映射

| 设计意图 | 画布 Kind |
|----------|-----------|
| 强主操作 | button + filled |
| 次操作 | button + outlined |
| 导航头 | topAppBar |
| 沉浸列表 | listItem 连接组 |
| 信息块 | card（elevated/tonal） |
| 分隔 | divider |
| 底导航 | bottomNav |
| 状态反馈 | badge / switch / checkbox |

生成 Doc 时 `theme` 建议显式写全：`dark, shape: rounded, font: roboto, motion: standard|expressive, contrast: standard`。
